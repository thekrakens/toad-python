# TOAD Productivity v0.1.0: Core Task Metrics Plan

This document outlines the planned metrics for the task-level database in Notion. The goal is to keep Notion lightweight with native formulas where possible, while leveraging the TOAD analytics engine for more complex calculations.

---

## Task Database Schema

### ━━━━━━ BASIC INFO ━━━━━━
- **Status**: (Status) The primary status of the task (e.g., To Do, In Progress, Done).
- **Task Type**: (Select) The category of the task (e.g., Work, Personal, Learning).
- **Est. Hrs**: (Number) Estimated hours required to complete the task.
- **Logged Hrs**: (Rollup) Sum of hours from related `Time Entries`.

### ━━━━━━ PLANNING ━━━━━━
- **Due**: (Date) The final deadline for the task.
- **Planned**: (Date Range) The intended start and end time for working on the task.
- **Doing**: (Date) Manually set to indicate when the task is actively being worked on.
- **Done**: (Date) Automatically set when the task `Status` is changed to "Done".

### ━━━━━━ FLAGS (Hidden Notion Formulas) ━━━━━━
These properties are calculated in real-time using Notion formulas and are intended to be hidden in most views. They provide signals for other metrics.

- **Active**: `if(or(or(or(formatDate(prop("Due"), "Y-MM-DD") == formatDate(now(), "Y-MM-DD"), formatDate(start(prop("Planned")), "Y-MM-DD") == formatDate(now(), "Y-MM-DD")), formatDate(prop("Doing"), "Y-MM-DD") == formatDate(now(), "Y-MM-DD")), formatDate(prop("Done"), "Y-MM-DD") == formatDate(now(), "Y-MM-DD")), 1, 0)`
  - *Checks if `Due`, `Planned` (start date), `Doing`, or `Done` is today.*
- **Worked**: `if(prop("Logged Hrs") > 0 and formatDate(prop("Last Edited"), "Y-MM-DD") == formatDate(now(), "Y-MM-DD"), 1, 0)`
  - *A proxy to check if the task was edited today and has logged hours. True accuracy will come from TOAD.*
- **Done Flag**: `if(formatDate(prop("Done"), "Y-MM-DD") == formatDate(now(), "Y-MM-DD"), 1, 0)`
- **Planned Flag**: `if(formatDate(start(prop("Planned")), "Y-MM-DD") == formatDate(now(), "Y-MM-DD"), 1, 0)`
- **Unplanned**: `if(and(prop("Worked") == 1, prop("Planned Flag") == 0), 1, 0)`
- **hasTimeBlocks**: `if(not empty(prop("Time Blocks")), 1, 0)`

### ━━━━━━ AUTO METRICS (Notion Formula) ━━━━━━

- **State**: 
  ```
  if(prop("Status") == "Done", "Done", if(prop("Due") < now() and empty(prop("Done")), "Overdue", if(prop("Worked") == 1, "Active", if(prop("Planned Flag") == 1, "Planned", if(dateBetween(now(), prop("Created"), "days") > 14 and empty(prop("Logged Hrs")), "Cold", "New")))))
  ```
  - **Note**: This formula provides a text-only state. Use Notion's **Conditional Formatting** feature to apply background colors for a clean, visual representation without emojis.
    - `Done`: Green background
    - `Overdue`: Red background
    - `Active`: Blue background

## Advanced Metrics (Calculated by TOAD)

These metrics require more complex logic and will be calculated by the TOAD analytics engine and pushed back to the Notion Tasks database.

**1. Performance Score (Number)**
- **Concept:** A single score (0-100) rating the overall execution of a task.
- **Calculation:** A weighted average of:
    - **On-Time Completion (40%):** `100` if `Done Date` <= `Due Date`, else `0`.
    - **Estimation Accuracy (30%):** `(1 - abs(Est. Hrs - Logged Hrs) / Est. Hrs) * 100`.
    - **Schedule Adherence (20%):** Percentage of work sessions that occurred within the `Planned` date range.
    - **Focus (10%):** `1 / (Number of distinct work days)`.

**2. Efficiency (Select)**
- **Concept:** A qualitative measure of time estimation accuracy.
- **Values:** `Under-estimated`, `Well-estimated`, `Over-estimated`.
- **Calculation:**
    - `Over-estimated`: If `Logged Hrs` > `Est. Hrs` * 1.2.
    - `Under-estimated`: If `Logged Hrs` < `Est. Hrs` * 0.8.
    - `Well-estimated`: Otherwise.

**3. Work Sessions (Number)**
- **Concept:** The number of distinct time entries (work sessions) for the task.
- **Calculation:** A count of the `Time Entries` relation.
- **Purpose:** A proxy for focus and context switching.

**4. On-Time Status (Select)**
- **Concept:** A clear status on whether the task was completed on time relative to its due date.
- **Values:** `Early`, `On Time`, `Late`, `Very Late`.
- **Calculation:**
    - `Early`: If `Done Date` < `Due Date`.
    - `On Time`: If `Done Date` is the same day as `Due Date`.
    - `Late`: If `Done Date` is 1-3 days after `Due Date`.
    - `Very Late`: If `Done Date` is >3 days after `Due Date`.

## Handling Transient Data

- **Problem**: The state of a task (e.g., "Active") on a specific day is ephemeral and lost if not captured on that day.
- **Solution**: The TOAD-powered `Daily Metrics` sync is the robust solution.
  - The `toad metrics sync` command will run daily.
  - It will use the `DailyMetricsCalculator` to identify all tasks that were `Active`, `Planned`, `Worked On`, and `Completed` on that specific day.
  - It will create relations in the `Daily Metrics` table to these tasks.
  - This approach provides an accurate, historical record for trend analysis, solving the transient state problem. Manual sync is a known limitation; future work could involve automating this process via a scheduler (e.g., cron job, GitHub Actions).
