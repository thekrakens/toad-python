## Overview

### Problem Statement

Currently tracking fitness data across multiple disconnected systems:
- **Gymaholic app**: Strength training data locked in CSV exports
- **Apple Health**: Cardio/climbing data not integrated with productivity system
- **Habit Tracker**: Manual checkbox entry, no workout details or summaries
- **Health Stats Table**: Broken Notion formulas, can't visualize weight/calories trends
- **No progression tracking**: Can't see strength gains or identify when to increase weight
- **No historical analysis**: Can't review past workouts or track personal bests

This creates friction in the tracking process and provides no insights into fitness progress.

### Goals

- [ ] **G1: Automated Workout Import** - Process Gymaholic CSVs and Apple Health data automatically
- [ ] **G2: Notion Integration** - Auto-check habit tracker boxes, generate workout summaries
- [ ] **G3: Fix Health Stats ETL** - Replace broken formulas with TOAD transformation pipeline
- [ ] **G4: Data Visibility** - View workout history and details in Notion databases
- [ ] **G5: Open Source Ready** - Flexible data source plugins for community use

### Non-Goals (Deferred to v0.2.1+)

- Progression detection and weight increase suggestions (v0.2.1)
- Personal best tracking for runs/climbs (v0.2.1)
- Discord integration for workout posts (v0.3.0)
- Exercise library with form cues (v0.3.0)
- Detailed sets tracking for strength workouts (v0.2.1)

### Success Criteria

- [ ] **SC1**: Drop Gymaholic CSV in iCloud folder → auto-synced to Notion within 30 min
- [ ] **SC2**: Habit tracker checkboxes auto-checked based on workout type
- [ ] **SC3**: Workout summaries auto-generated in habit tracker page content
- [ ] **SC4**: Health Stats table populated via TOAD ETL (weight, bf%, cals) for charting
- [ ] **SC5**: Test coverage >85% for health module
- [ ] **SC6**: Works for other users with minimal configuration

## Data Model

### Notion Database Schemas

#### Database 1: Habit Tracker (EXISTING - Updates Required)

**Purpose:** Daily habit logging and entry point for all health data

**Current Properties:** 27 properties including:
- `Date` (date) - Primary key
- `run` (checkbox) - Already exists ✅
- `Climb` (checkbox) - Already exists ✅
- `lbs` (number) - Weight in pounds
- `bf %` (number) - Body fat percentage
- `in` (number) - Calories in
- `out` (number) - Calories out
- `Name` (title) - Page title

**Required Updates:**
- [ ] Add `Workout` (checkbox) - For strength training

**TOAD Responsibilities:**
- Auto-check `Workout`, `run`, `Climb` boxes when workouts detected
- Generate workout summary in page content block
- Extract `lbs`, `bf %`, `in`, `out` for Health Stats ETL

#### Database 2: Workouts (NEW - Hidden Database)

**Purpose:** Store detailed workout data from Gymaholic and Apple Health

| Property | Type | Description | Required | Auto-populated |
|----------|------|-------------|----------|----------------|
| Name | Title | Auto-generated (e.g., "TOMO B Strength - Jan 18") | Yes | Yes |
| Date | Date | Workout date | Yes | Yes |
| Type | Select | Strength, Run, Climb, Hike, Walk | Yes | Yes |
| Source | Select | Gymaholic, Apple Health, Manual | Yes | Yes |
| Duration | Number | Minutes | No | Yes |
| Calories | Number | Calories burned | No | Yes |
| Avg HR | Number | Average heart rate (bpm) | No | Yes |
| Distance | Number | Miles (for cardio) | No | Yes |
| Elevation | Number | Feet (for hiking/climbing) | No | Yes |
| Notes | Rich Text | User notes or auto-summary | No | Yes |
| Habit Entry | Relation | → Habit Tracker (many:1) | Yes | Yes |
| Raw Data | Files | Original CSV/JSON file | No | Yes |
| Created | Created Time | Auto timestamp | Yes | Yes |

**Select Options:**
- Type: `Strength`, `Run`, `Climb`, `Hike`, `Walk`, `Other`
- Source: `Gymaholic`, `Apple Health Export`, `Health Auto Export`, `Manual`

**Relations:**
- → Habit Tracker: Links to daily habit entry for that date

#### Database 3: Health Stats (EXISTING - ETL Redesign)

**Purpose:** Time-series data for charting weight, body fat, and calorie trends

**Current Properties:** 7 properties (mostly formulas - TO BE REPLACED)

**New TOAD-Managed Schema:**

| Property | Type | Description | Source |
|----------|------|-------------|--------|
| title | Title | Auto: "{tag} - {date}" | TOAD |
| date | Date | Date of measurement | TOAD |
| tags | Select | lbs, bf, cals_in, cals_out | TOAD |
| value | Number | The metric value | TOAD |
| date (mm/dd) | Formula | `formatDate(prop("date"), "MM/DD")` | Notion |
| relative values | Formula | Percent change from baseline | Notion |
| percentage | Formula | Visual percentage bar | Notion |

**TOAD ETL Process:**
1. Extract: Read Habit Tracker entries with `lbs`, `bf %`, `in`, `out`
2. Transform: Convert to time-series format (one row per metric per day)
3. Load: Upsert to Health Stats (create or update entries)
4. Schedule: Run on 30-min or 6-hour sync cycle

**Example Transformation:**
```
Habit Tracker entry (Jan 18):
  Date: 2026-01-18
  lbs: 175
  bf %: 15
  in: 2200
  out: 2800

→ Transforms to 4 Health Stats entries:
  1. title="lbs - 01/18", date=2026-01-18, tags=lbs, value=175
  2. title="bf - 01/18", date=2026-01-18, tags=bf, value=15
  3. title="cals_in - 01/18", date=2026-01-18, tags=cals_in, value=2200
  4. title="cals_out - 01/18", date=2026-01-18, tags=cals_out, value=2800
```

### Python Data Structures

```python
# toad/health/models.py
from dataclasses import dataclass
from datetime import datetime
from typing import Optional, List

@dataclass
class WorkoutData:
    """Represents a parsed workout session."""
    date: datetime
    workout_type: str  # Strength, Run, Climb, etc.
    source: str  # Gymaholic, Apple Health, etc.
    duration_minutes: Optional[int] = None
    calories: Optional[int] = None
    avg_heart_rate: Optional[int] = None
    distance_miles: Optional[float] = None
    elevation_feet: Optional[int] = None
    notes: Optional[str] = None
    raw_file_path: Optional[str] = None
    exercises: Optional[List['ExerciseData']] = None  # For strength workouts

@dataclass
class ExerciseData:
    """Represents a single exercise within a strength workout."""
    name: str
    sets: int
    reps: List[int]  # Reps per set
    weight: List[float]  # Weight per set (lbs)
    notes: Optional[str] = None

@dataclass
class HealthMetric:
    """Represents a single health metric for Health Stats table."""
    date: datetime
    tag: str  # lbs, bf, cals_in, cals_out
    value: float
```

## Performance Considerations

### API Usage

**Estimated API Calls per Sync:**

**Workout Sync (30-min cycle):**
- Check for existing workout (duplicate detection): 1 call
- Create workout entry: 1 call
- Update habit tracker checkbox: 1 call
- Update habit tracker page content: 1 call (same as checkbox update)
- **Total per workout: ~3 calls**

**Health Stats ETL (6-hour cycle, 30 days of data):**
- Query Habit Tracker for date range: 1-2 calls (pagination)
- Query Health Stats for existing entries: 1-2 calls
- Upsert Health Stats entries (batch): 2-4 calls (4 metrics × 30 days = 120 entries, batched)
- **Total per run: ~6-8 calls**

**Daily Total Estimate:**
- Workout syncs: 48 runs × 1 workout avg × 3 calls = ~144 calls/day
- Health Stats ETL: 4 runs × 8 calls = ~32 calls/day
- **Combined: ~176 calls/day for health module**
- **Plus existing productivity: ~1,152 calls/day**
- **Grand total: ~1,328 calls/day = 0.9 calls/min** ✅ Well under 3/sec limit

### Rate Limit Strategy

- Use batching for Health Stats upserts (update multiple entries per API call)
- Implement exponential backoff on rate limit errors
- Add configurable delays between API calls if needed
- Monitor API usage in logs

### Processing Time

**Target Performance:**
- Workout sync (single file): <30 seconds
- Health Stats ETL (30 days): <60 seconds
- Both fit comfortably within sync cycle windows

**Bottlenecks:**
- Notion API latency (network calls)
- CSV/XML parsing (negligible for workout sizes)
- File I/O (iCloud Drive sync lag)

**Optimizations:**
- Cache parsed data to avoid re-parsing
- Batch Notion updates where possible
- Use incremental ETL (only process changed dates)

## Security & Privacy

### Data Handling

**Sensitive Data:**
- Health metrics (weight, body fat %, workout details)
- Location data (if included in Apple Health exports)

**Storage:**
- Original files: Archived in `processed/` folder (local iCloud Drive)
- Parsed data: Stored in Notion (user's private workspace)
- No cloud storage of raw files by TOAD

**Encryption:**
- Files stored in iCloud Drive (encrypted by Apple)
- Notion API uses HTTPS
- No additional encryption needed at TOAD layer
